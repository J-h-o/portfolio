# I18N.md — English and Greek localization

The site ships complete English and Greek variants. Localization is server-rendered and statically generated; it is not a client-side text replacement layer.

## URL and preference model

- English: `/en`, `/en/services`, `/en/portfolio/...`
- Greek: `/el`, `/el/services`, `/el/portfolio/...`
- An unprefixed URL redirects to English for a first-time visitor.
- Selecting a language stores `NEXT_LOCALE` for one year. Later unprefixed visits redirect to the saved locale.
- The language switcher preserves the current page and case-study slug.
- `proxy.ts` handles only locale redirects and skips APIs, Next.js assets, public files, and metadata routes.

## Source layout

| File | Responsibility |
|---|---|
| `content/i18n.ts` | Supported locales, type guard, URL helpers, language tags |
| `content/dictionary.ts` | Page-level UI, actions, form labels, metadata, empty/error states |
| `content/site.ts` | Localized navigation, services, and process |
| `content/experience.ts` | Localized bio, work history, skills, credentials |
| `content/projects.ts` | Localized case studies with shared stable slugs |
| `app/[locale]/` | Locale-aware SSG routes and `<html lang>` |
| `components/language-switcher.tsx` | Small client leaf that swaps locale while preserving the path |

## Translation rules

- Translate meaning and professional intent, not English word order.
- Keep company/product names, framework names, acronyms, and established technical vocabulary where translating would reduce clarity: React, Flutter, backend, RAG, LLM, CI/CD, CMS, analytics.
- Translate explanatory technical terms when a natural Greek equivalent exists: vector search → διανυσματική αναζήτηση, document intelligence → κατανόηση εγγράφων.
- Preserve every verified metric exactly; use Greek decimal punctuation in Greek copy (`2,5 εκ.`) without changing the value.
- Do not add biographical facts, client claims, or outcomes during translation.
- Greek CTAs should sound natural in context: `Κλείστε ραντεβού`, not a literal rendering of “book a call.”
- New content is incomplete until both languages, metadata, structured data, and tests are updated.

## SEO contract

Each localized page includes:

- its own canonical locale-prefixed URL;
- reciprocal `en-GB` and `el-GR` alternates plus `x-default` pointing to English;
- localized title and description;
- localized JSON-LD text with an `inLanguage` value;
- sitemap entries for both languages with alternate-language mappings.

Case-study slugs intentionally remain identical between languages so language switching is deterministic and external links stay stable.

## Adding another locale

1. Add the locale and language tag to `content/i18n.ts`.
2. Add a complete dictionary and localized variants of site, experience, and project content.
3. Extend `getDictionary`, `getSiteContent`, `getExperienceContent`, and project getters.
4. Add locale-specific structured-data language/text where needed.
5. Extend content integrity tests and visually inspect desktop/mobile navigation and long headings.
